# AskDrKristof — MVP v1 UI / UX Spec
## AI Between-Session Companion for Existing Hypnosis Clients

**Version:** MVP v1  
**Document Type:** UI / UX Specification  
**Purpose:** Define the intended client experience, interaction design principles, and interface behavior  
**Scope:** Product feel, navigation, interaction patterns, trust design, visual tone, usability behavior  
**Implementation Note:** This spec intentionally describes the desired experience and principles, not exact UI implementation details

---

# 1. Purpose of This Document

This document defines what the **AskDrKristof user experience should feel like**.

It is not a visual design system and not a front-end implementation plan.

It exists to ensure the product is built with the right:
- emotional feel
- interaction shape
- trust model
- user guidance
- behavioral clarity

The product should feel:
> **calm, clear, structured, private, and useful**

That matters as much as the AI itself.

---

# 2. Core UX Philosophy

AskDrKristof should not feel like:
- generic ChatGPT
- a support chatbot from a telecom company
- a productivity app
- a mystical wellness app
- a “talk to AI about anything” toy

It should feel like:
> **a private, structured therapeutic support companion**

The experience should communicate:
- containment
- clarity
- professionalism
- warmth without fluff
- seriousness without coldness

---

# 3. UX Goals

The interface should help the user:

1. know what the tool is for
2. know what the tool is not for
3. quickly find the kind of help they need
4. avoid blank-page / blank-chat paralysis
5. feel psychologically safe and not overwhelmed
6. leave with something useful in a short interaction
7. trust the product without confusing it for Dr Kristof

Those are the core UX jobs.

---

# 4. Core UX Principles

---

## Principle 1 — **Structured > open-ended**

The assistant should not open primarily into an empty chat box.

That creates:
- uncertainty
- vague usage
- low-signal interactions
- weaker product learning
- more safety ambiguity

Instead, the product should be built around:
> **guided modes first, chat second**

This is one of the most important UX principles in the entire product.

---

## Principle 2 — **Reduce emotional friction**

Users often open tools like this when they are:
- unsure
- emotionally activated
- confused
- tired
- mildly overwhelmed

The interface should reduce friction by making the next step obvious.

The product should never feel like:
> “figure it out yourself”

It should feel like:
> “you are being gently guided”

---

## Principle 3 — **Containment over stimulation**

This product should not be visually or behaviorally stimulating.

Avoid design patterns that feel:
- gamified
- dopamine-heavy
- loud
- hyper-animated
- overly “delightful”
- social-media-like

This is not the right emotional frame.

The product should feel:
- spacious
- stable
- calm
- clean
- emotionally breathable

---

## Principle 4 — **Trust should be visible in the interface**

Trust should not rely only on disclaimers hidden in settings.

The UI should visibly communicate:
- what this is
- what it helps with
- that it is AI
- that it is not a replacement for live support

This should be embedded into the product experience itself.

---

## Principle 5 — **Short useful interactions should feel complete**

A user should be able to:
- open the product
- use it for 2–5 minutes
- get something useful
- leave feeling more oriented

That should feel like a success.

The product should not be designed as if “longer use = better use.”

That is not the right optimization.

---

# 5. Emotional Feel of the Product

If the interface had a personality, it should feel:

- calm
- quiet
- intelligent
- private
- grounded
- respectful
- steady
- not sterile
- not spiritualized
- not clinical in a hospital way

The emotional design should support:
> **psychological containment**

That is a very important design goal.

---

# 6. Product Entry Experience

The first moments matter a lot.

When a client opens AskDrKristof, the interface should immediately answer:

- What is this?
- What can I do here?
- Is this safe to use?
- Where do I start?

---

# 7. First-Time Onboarding Experience

The first-time experience should be short and very clear.

It should establish four things:

## 1. Identity
This is an AI support companion trained on Dr Kristof’s materials and approach.

## 2. Usefulness
It can help with:
- reflection
- process questions
- trigger mapping
- reinforcement
- session prep

## 3. Boundaries
It is not:
- Dr Kristof
- crisis support
- emergency support
- a replacement for live sessions

## 4. Consent / acknowledgment
The user should actively confirm understanding.

This should be simple, not heavy.

---

# 8. Home Screen Design Intent

The home screen should not feel like:
> “type anything”

It should feel like:
> “choose what kind of help you want right now”

This is the main structural UX decision.

---

# 9. Home Screen Core Prompt

The primary prompt should be something like:

## **What would help most right now?**

This is much better than:
- “How can I help?”
- “Ask me anything”
- “What’s on your mind?”

Because it immediately creates:
- orientation
- structure
- usefulness

---

# 10. Primary Guided Actions

The home screen should prominently surface the 6 core modes:

- Reflect on what came up
- Work through a trigger
- Reinforce this week’s progress
- Prepare for next session
- Ask about hypnosis or the process
- Ask about what I’m experiencing

These should be visually clear and easy to tap.

This is the main product surface.

---

# 11. Secondary Free-Text Entry

A free-text input should still exist.

But it should feel like:
> “you can type if you need to”

—not:
> “this is primarily an open chatbot”

This preserves flexibility without losing structure.

---

# 12. UX for Guided Mode Entry

When a user chooses a guided mode, the interface should make the transition feel intentional.

The user should feel:
- “I’m now doing something specific”
- “I don’t have to figure out what to say from scratch”

Each mode should ideally begin with:
- a short explanation of what this mode is for
- a clear first prompt

This reduces uncertainty and improves quality of use.

---

# 13. Conversation Screen UX

The conversation screen should feel:

- calm
- uncluttered
- readable
- non-busy
- emotionally low-pressure

Avoid:
- noisy visual chrome
- excessive icons
- too many floating actions
- distracting visual effects

The user should feel like:
> “I can think here.”

That matters a lot.

---

# 14. Message Design Principles

Messages should be easy to read and psychologically lightweight.

The UI should support:
- comfortable reading pace
- low cognitive load
- clear separation between assistant and user
- a sense of conversational safety

The visual language should not feel:
- gamified
- social
- chaotic
- “chat app for fun”

This is a professional support product.

---

# 15. Input Experience

The input area should support both:

- typed free text
- guided interaction continuation

The user should not feel trapped in either:
- fully scripted flow
or
- blank open chat

The best experience is:
> **structured flexibility**

That is the right balance.

---

# 16. Follow-Up Prompt UX

The assistant will often ask follow-up questions.

These should feel easy to answer.

The interface should support the feeling of:
- “I can answer simply”
- “I don’t need to write an essay”

This can be supported through:
- concise prompts
- optional suggested replies
- short interaction scaffolding

The exact implementation is open, but the UX principle is:
> **lower the effort required to continue**

---

# 17. Session Summary UX

One of the most valuable product behaviors is helping the user leave with a useful takeaway.

This should be reflected in the interface.

After a meaningful interaction, the UI should make the ending feel complete.

The user should not feel like the conversation just “stops.”

---

# 18. End-of-Conversation Experience

At the end of a meaningful interaction, the interface should help surface something like:

- **What stood out**
- **What may be worth bringing into your next session**
- **A useful takeaway**
- **A reflection summary**
- **A next-session note**

This is a major UX opportunity.

It turns “chat” into something more valuable and usable.

---

# 19. Save / Review / Return UX

The product should support the feeling that:
> “what I did here matters and can be returned to”

Users should be able to feel that their interactions are not disposable.

Especially useful things to preserve access to:
- trigger reflections
- session prep notes
- useful summaries
- recurring themes

The exact mechanism is open, but continuity should feel available.

---

# 20. Privacy & Emotional Safety UX

Because this is a psychologically sensitive product, the interface should feel private.

That means the product should avoid cues that feel:
- public
- performative
- social
- exposed

The user should feel:
> “this is for me, not for display”

This matters deeply in this category.

---

# 21. Transparency UX

The product should make it clear that:
- this is AI
- it is trained on Dr Kristof’s materials
- it is not Dr Kristof

This should be visible in the interface, not hidden.

But it should be done elegantly, not defensively.

The ideal feel is:
> **clear enough to prevent confusion, subtle enough not to feel repetitive**

---

# 22. Safety UX

The UI should support the product’s safety boundaries in a way that feels natural.

That means the interface should not accidentally imply:
- “this is for everything”
- “this is 24/7 emotional rescue”
- “you can use this instead of live support”

The product should gently but clearly communicate:
- intended use
- non-intended use
- support boundaries

This should happen through:
- onboarding
- microcopy
- interaction design
- escalation states

Not only through a legal disclaimer.

---

# 23. Escalation UX

When the assistant encounters out-of-scope or unsafe content, the UI should support a different conversational state.

That state should feel:
- serious
- clear
- calm
- non-panicked
- non-generic

The user should be able to feel:
> “the system recognizes this is different”

This should not feel like:
- a moderation slap
- a generic safety wall
- a jarring AI refusal

It should feel like:
> **a boundary with dignity**

That is important.

---

# 24. UX for “Is This Normal?” Use Cases

This is likely to be one of the most-used product surfaces.

That means it should be especially frictionless.

Users asking:
- “is this normal?”
- “should I worry?”
- “what does this mean?”

are often in a lightly activated state.

The UX should support:
- fast entry
- low typing burden
- calming orientation
- clear and bounded answers

This mode is likely to become a flagship experience.

---

# 25. UX for Trigger Reflection

This mode should feel like:
> **gentle guided pattern mapping**

Not:
- a journaling app
- a therapy worksheet
- a heavy trauma tool

The user should feel:
- “I can map this without getting lost in it”

This is an important UX distinction.

---

# 26. UX for Process Questions

This mode should feel:
- confidence-building
- simple
- reassuring
- myth-clearing

Users in this mode often want:
- a fast answer
- a clear explanation
- relief from uncertainty

The UX should support that by being:
- low-friction
- low-drama
- direct

---

# 27. UX for Session Prep

This mode should feel like:
> **clarifying what matters before the next session**

Not:
- admin
- homework
- paperwork

The interface should help the user narrow down what matters most, not force them to produce a “perfect report.”

The emotional feel should be:
- thoughtful
- useful
- easy

---

# 28. Product Rhythm & Frequency UX

The product should feel appropriate for:
- quick check-ins
- short reflective moments
- occasional use between sessions

It should not visually or behaviorally pressure the user into:
- daily streaks
- compulsive check-ins
- dependency loops
- “come back every day” mechanics

This is not a habit app.

That is a very important UX principle.

---

# 29. Visual Tone Principles

Without prescribing exact UI design, the visual tone should generally support:

- softness without “wellness fluff”
- clarity without sterility
- premium simplicity
- calm spacing
- visual quietness
- low-arousal interaction

Avoid visual directions that feel:
- too medical
- too mystical
- too startup-hype
- too playful
- too gamified

The interface should feel:
> **serious, gentle, and high-trust**

---

# 30. Writing / Microcopy Principles

All UI copy should be:

- clear
- calm
- direct
- psychologically literate
- not overly “marketing”
- not overly clinical
- not mystical
- not cute

Good product writing in this app should feel like:
> “confidently calm”

Examples of good microcopy tone:
- “What would help most right now?”
- “What feels most worth understanding?”
- “Something to bring into your next session”
- “A useful takeaway”

Bad tone examples:
- “Unlock your subconscious power”
- “Tell us your deepest truth”
- “Ready for transformation?”
- “Let’s dive in!”

That is the wrong feel.

---

# 31. Empty / Idle State UX

When the user is not actively in a conversation, the product should still feel gently useful.

The idle state should support:
- orientation
- easy re-entry
- low-friction usefulness

This is a good place to reinforce:
- the 6 modes
- recent useful summaries
- session prep relevance
- low-pressure return

The product should never feel empty or dead, but also not busy or demanding.

---

# 32. MVP UX Success Criteria

The UX is successful if users consistently feel:

- “I know what this is for”
- “I know where to start”
- “This feels safe to use”
- “This helps me quickly”
- “This feels like Dr Kristof’s world, not generic AI”
- “I don’t feel lost or overwhelmed here”

That is the real UX success test.

---

# 33. Final UX Principle

If there is ever a design tradeoff between:
- more stimulation / engagement
and
- more clarity / calm / trust

the product should choose:

> **clarity, calm, and trust**

Always.

Because in this product category, the strongest UX is not the most exciting.

It is the one that feels:
- psychologically safe
- emotionally breathable
- quietly useful
- professionally grounded

That is what AskDrKristof should feel like.
