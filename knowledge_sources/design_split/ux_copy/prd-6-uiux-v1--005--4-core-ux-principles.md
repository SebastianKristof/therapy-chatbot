# 4. Core UX Principles

---

## Principle 1 — **Structured > open-ended**

The assistant should not open primarily into an empty chat box.

That creates:
- uncertainty
- vague usage
- low-signal interactions
- weaker product learning
- more safety ambiguity

Instead, the product should be built around:
> **guided modes first, chat second**

This is one of the most important UX principles in the entire product.

---

## Principle 2 — **Reduce emotional friction**

Users often open tools like this when they are:
- unsure
- emotionally activated
- confused
- tired
- mildly overwhelmed

The interface should reduce friction by making the next step obvious.

The product should never feel like:
> “figure it out yourself”

It should feel like:
> “you are being gently guided”

---

## Principle 3 — **Containment over stimulation**

This product should not be visually or behaviorally stimulating.

Avoid design patterns that feel:
- gamified
- dopamine-heavy
- loud
- hyper-animated
- overly “delightful”
- social-media-like

This is not the right emotional frame.

The product should feel:
- spacious
- stable
- calm
- clean
- emotionally breathable

---

## Principle 4 — **Trust should be visible in the interface**

Trust should not rely only on disclaimers hidden in settings.

The UI should visibly communicate:
- what this is
- what it helps with
- that it is AI
- that it is not a replacement for live support

This should be embedded into the product experience itself.

---

## Principle 5 — **Short useful interactions should feel complete**

A user should be able to:
- open the product
- use it for 2–5 minutes
- get something useful
- leave feeling more oriented

That should feel like a success.

The product should not be designed as if “longer use = better use.”

That is not the right optimization.
