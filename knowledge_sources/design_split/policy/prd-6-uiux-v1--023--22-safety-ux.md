# 22. Safety UX

The UI should support the product’s safety boundaries in a way that feels natural.

That means the interface should not accidentally imply:
- “this is for everything”
- “this is 24/7 emotional rescue”
- “you can use this instead of live support”

The product should gently but clearly communicate:
- intended use
- non-intended use
- support boundaries

This should happen through:
- onboarding
- microcopy
- interaction design
- escalation states

Not only through a legal disclaimer.
